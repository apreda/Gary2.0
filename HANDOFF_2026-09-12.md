## 5. How Adam works — read this before touching anything

These are standing laws from his own words. Violating them has cost real rework.

- **Never propose Gary decision rules.** Not as a suggestion, not as a question.
  "Should Gary avoid favorites over -150?" is the violation. Fix data order, data
  quality, or prompt *contracts* — never insert betting strategy.
- **No workarounds — fix the contract.** When a brain's output breaks a lane, fix the
  ask or the enforcement so the brain produces the right thing. Never rearrange,
  invent, or post-process its content.
- **Talk first, edit on GO.** No changes until his explicit go-ahead. Ambiguous
  "go ahead"? Ask.
- **Commit with a pathspec.** `git add <paths> && git commit -- <paths>`. Never
  `git add -A` — a peer agent may have work staged in the same checkout.
  `ios/GaryApp/GoogleService-Info.plist` stays uncommitted.
- **Anthropic API key = research only.** Never the brain, never props, never press
  searches. Bridges ($0 Claude/Codex subscriptions) carry everything else.
  `ANTHROPIC_API_KEY` must never reach the `claude` CLI — it hijacks it off the sub.
- **All times ET.** Game-day derivations in code too.
- **Gary is a character, never an AI.** No 4th-wall breaks in Gary-voiced copy. No
  emojis anywhere in his output. No betting-tool lingo (EV, CLV, "CALL").
- **Show complete content.** When he asks to read a prompt, print it in full, word for
  word. Never summarize or trim what he asked to see.
- **Report failures honestly.** If a test fails, show the output. If a step was
  skipped, say so.
